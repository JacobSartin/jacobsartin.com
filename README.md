# jacobsartin.com

Personal portfolio site, prerendered with [TanStack Start](https://tanstack.com/start/latest), [Vite+](https://viteplus.dev/), React, and [TanStack Router](https://tanstack.com/router/latest). jacobsartin.com is served from my homelab; CI also publishes a mirror to GitHub Pages.

The React imports run on [TanStack Redact](https://github.com/TanStack/redact) using its default feature preset, including hydration, context and Suspense. Rendering and transitions are synchronous; check Redact compatibility before introducing React action or concurrent rendering APIs. SSR dependencies are bundled together so prerendering uses the same runtime as the browser.

## Getting Started

React Compiler optimizes browser components through the official Vite React
preset and `@rolldown/plugin-babel`. Redact supplies the aliased
`react/compiler-runtime`; server prerendering keeps its existing pipeline.
Compare bundle sizes and exercise the picker, theme controls, navigation and
hydration when changing compiler or runtime versions. This integration enables
automatic memoization; it does not establish a measured speed improvement.

Use Node.js 22.18+, 24.11+, or 26+ (CI uses Node.js 24). The pnpm version is pinned through the `packageManager` field in `package.json`, and pnpm switches to it automatically. From the repository root, install dependencies and start the dev server:

```bash
pnpm install
pnpm dev
```

Open <http://localhost:5173> in your browser.

## Scripts

- `pnpm dev`: start the Vite+ dev server
- `pnpm build`: build the production bundle into `dist/`, then run the post-build step
- `pnpm check`: check formatting, lint rules, and TypeScript types with Vite+
- `pnpm fmt`: format the project with Vite+
- `pnpm typecheck`: type-check the project with `tsc --noEmit`
- `pnpm start`: preview the production build locally
- `pnpm size`: build and report initial/deferred JS/CSS sizes (raw, gzip, and Brotli)

Vite+ is installed locally, so no global CLI is required. `vite.config.ts` holds the build, lint, and format settings; `pnpm-workspace.yaml` pins Vite+ and aliases Vite to the matching Vite+ core so plugins share one toolchain. Keep those versions aligned when upgrading. The project retains its existing 80-column formatting preference.

With the optional global `vp` CLI, use `vp install`, `vp dev`, `vp run check`, and `vp run build`. Use `vp run build` instead of the bare `vp build` command when you need the complete static site, including prerendered pages and the 404 fallback. `vp build` bundles and prerenders; the complete script also verifies the static output and creates `.nojekyll`.

## Dependency Updates

The [Renovate configuration](.github/renovate.json5) manages npm packages, the pnpm version, the Vite+ catalog, and GitHub Actions. Updates are proposed weekly with a three-day release cooldown and manual merging. Related React, TanStack Router/Start, and Vite+ packages update together. Node types stay on the Node 24 line used in CI.

CI audits dependencies on pull requests and every Monday at 13:00 UTC, as well as checking and building the site. Run `pnpm audit --audit-level=high` locally for the same vulnerability check. The weekly run also checks for advisories affecting an unchanged lockfile.

The Dependency graph workflow submits the resolved pnpm dependencies to GitHub on pushes to `main`. This restores dependency graph coverage for pnpm 12's two-document lockfile without changing its format or weakening package-manager version enforcement. Enable Dependabot alerts in the repository settings to receive vulnerability alerts for the submitted dependencies.

## Project Layout

- `src/router.tsx`: router configuration, intent preloading and scroll restoration
- `src/routes/`: typed route definitions and root layout.
- `src/routes/projects/<slug>/index.tsx`: each project owns its route, metadata and JSX in one file, with its own folder for supporting files.
- `src/routeTree.gen.ts`: generated route types and imports, committed to Git. Do not edit this file by hand.
- `src/page.tsx`, `src/about/`, `src/skills/`, `src/projects/`: page components and their styles
- `src/projects/cards.ts`: project metadata shared by routing and the listing
- `src/components/`: shared UI (nav, cards, theme and accent controls, project template)
- `src/globals.css`: design tokens (spacing, colors, widths) and shared utilities

The bundler regenerates `src/routeTree.gen.ts` during development and builds. Commit its changes alongside route additions, moves or deletions so a fresh checkout has route types available before the first build. The generated file is excluded from formatting and linting; type checking uses its declarations. `.tanstack/` contains ignored build intermediates.

To add a project, create `src/routes/projects/<slug>/index.tsx` with a named component and an exported `Route = createFileRoute("/projects/<slug>/")({ component: ProjectPage, head: ... })`. Add its listing card to `src/projects/cards.ts`. Supporting modules inside route folders should use TanStack’s `-` filename prefix so they are excluded from route discovery. The page content stays in its own TSX; there is no generic project renderer or separate route wrapper.

Home loads eagerly. Secondary routes and their CSS load on navigation or link intent; the projects listing does not fetch every detail page. The accent picker and color libraries stay out of the initial bundle. After the page's load event, the control warms them during browser idle time (within one second, or after a short timer on browsers without idle callbacks). Hover, keyboard focus, or pointer down starts loading sooner. Warming and opening share one request; warming never mounts or opens the picker.

The accent picker uses the native [Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API) for its top layer, dismissal, and focus behavior. CSS anchor positioning attaches it to its trigger on roomy screens. Small viewports and browsers without the required anchor sizing support use a centered, scrollable panel. Browser toggle events synchronize drafts and accessibility state; the picker has no custom position calculations or resize/scroll listeners. Browsers must support the Popover API; CSS anchor positioning is an optional enhancement.

Route metadata is rendered by `HeadContent`, including page titles, descriptions and social tags. A catch-all route supplies not-found metadata. Router Devtools are available in development and excluded from production. Add new internal project links using the generated route types so invalid destinations fail type checking.

JetBrains Mono's Latin variable WOFF2 (weights 400–700, Google Fonts v24) is
bundled from `src/assets/jetbrains-mono-latin-wght.woff2` and preloaded by the root
document. Its SIL Open Font License is in `public/licenses/jetbrains-mono.txt`.
`font-display: optional` keeps the fallback for the current visit if the font
arrives too late for first paint, avoiding text resizing on a cold connection.
Both theme icons are prerendered; CSS selects the visible one from the theme applied by the document bootstrap before paint.

## Deployment

Every push to `main` runs `.github/workflows/deploy.yaml`. It builds the site, then force-pushes `dist/` to the `site` branch as a single commit. jacobsartin.com serves whatever that branch holds and picks up a new build within about a minute.

To roll back, revert the commit on `main`, or re-run an earlier Deploy run.

A deploy replaces the previous build's hashed chunks. The document bootstrap in `src/utils/bootstrap.ts` reloads once when an old page cannot load a replaced chunk. That bootstrap also applies persisted theme/accent preferences before first paint.

CI and both deployment workflows use `voidzero-dev/setup-vp` to install Node.js, the pinned Vite+ toolchain, and dependencies with a frozen lockfile. Builds run through `vp run build` so the post-build step is included. The separate Dependency graph workflow reads the manifests and lockfile without installing dependencies.

Each workflow passes the checked-out source commit as `VITE_COMMIT_SHA`. The shared footer displays its first seven characters and links to the full commit on GitHub. The value is embedded during the build, including prerendered pages and the 404 fallback, so it identifies the source used for that deployment rather than the generated `site` branch commit. Local development and builds omit the footer unless `VITE_COMMIT_SHA` is set.

`.github/workflows/ci.yaml` runs `pnpm check` and builds every pull request. `.github/workflows/gh-pages.yaml` builds every push to `main` and deploys `dist/` to the GitHub Pages mirror at <https://jacobsartin.github.io/jacobsartin.com/>. The site base path comes from `VITE_BASE_PATH` and defaults to `/`.

Start prerenders every page into `<route>/index.html`, including page content, unique titles, descriptions and sharing metadata. A separate SPA shell becomes `404.html` for static-host unknown paths. The postbuild step verifies each page and fallback, then creates `.nojekyll`.

Start renders pages only during the build. Production serves static HTML, CSS and JavaScript, with navigation and interactions running in the browser. No request-time rendering, server functions or Start server are deployed.

Only `dist/` is published. `.tanstack/server/` contains the temporary server used during prerendering and is ignored by Git. Both the default `/` base and the GitHub Pages `/jacobsartin.com/` base are supported. Run the complete `pnpm build` to verify prerendered output before deployment.
